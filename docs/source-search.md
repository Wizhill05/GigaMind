# Legacy source search

Text searches scan the complete filtered legacy memory and profile corpus for case-folded terms, including short and Unicode terms. One- and two-character ASCII terms match whole words, so `Go` does not match `Django`; longer and non-ASCII terms match substrings. Results identify their retrieval method; scores are raw and uncalibrated. A missing or unavailable embedding provider leaves lexical retrieval available, but cannot supply semantic matches. No lexical match is an empty result when vector retrieval is unavailable. Image searches require a PNG or JPEG signature and an available embedding provider. Invalid input returns HTTP422; unavailable image embedding returns HTTP503. Missing, rejected or malformed provider responses allow text-only lexical fallback. Client authorization and database/programming failures do not fall back. Configured external rerankers may still receive queries and candidate text, even when embedding is unavailable.

File text search streams every published summary and chunk after SQL source and deletion filters. It searches persisted text, not remote bytes, unpublished extraction, or pending uploads. Files use category `file`; other category filters exclude them. Chunks inherit source identity only from a parent matching both file ID and storage key. Orphaned legacy chunks are searchable without a source filter, but cannot satisfy a source-specific request.

Each retrieval method retains a bounded pool of unique files. The final reranker receives at most twice `max(25, limit)` candidates, with space reserved for lexical and vector evidence. This prevents a full vector pool from suppressing exact lexical matches. Native vector queries remain bounded nearest-neighbor queries; SQLite streams valid stored vectors. The highest-ranked evidence per file is returned, with up to eight representative matching pages. Raw vector scores describe the selected record, not a calibrated confidence. Source IDs are table-local; use `file_key` as the canonical file identity.

URL generation occurs only for bounded candidates and uses lifecycle admission after the scan transaction ends. Deleted resources cannot obtain a new URL after their deletion commits. Previously issued URLs retain their documented expiry. Semantic relevance and reliable semantic no-match thresholds still require quality evaluation. Lexical scans have linear corpus cost; a full-text index is not implemented here.
